### 2.4 paircheck implemented (TDD, 9 planned steps)

**Problem:** Implement the ordering analyzer per PRD v0.3/v0.4.
**Solution:** Package `paircheck/`, public API:
- `New(Config) (*analysis.Analyzer, error)`;
- `Validate(Config, []*types.Package) error`;
- `Packages(Config) ([]string, error)`;
- the types `Config`, `Rule`, `Call`, `Coverage` and `Transfer`, and the sentinels.

It requires only `buildssa`. Files:
- `name.go`: FullName parsing and matching;
- `slot.go`, `bind.go`: per-pass resolution and slot by type;
- `flow.go`: path search with a 0/1/2+ count;
- `failure.go`: the error branch, following the variable a captured `err` is stored in;
- `identity.go`: access paths and `sameness`;
- `closure.go`: deferred closures;
- `transfer.go`: return, store and argument;
- `diagnostic.go`;
- `validate.go`.

Each step went red on assertions before green, and the red outputs were quoted in the conversation.
**Files:** `paircheck/*.go`, `paircheck/testdata/src/**` (commit `3448bbb`)
